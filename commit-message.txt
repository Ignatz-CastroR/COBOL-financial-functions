Initial project scaffold: structure, conventions, and tooling

This commit establishes the project's full organizational skeleton
ahead of any function implementation. No COBOL or FORTRAN source code
is included yet; every SRC/ subfolder currently holds only its own
README.md, documenting what that domain will implement once work
begins.

Structure:
* SRC/ organized by domain, one subfolder per financial, actuarial,
  or statistical concern, following a strict fan-in discipline:
  a function lives privately with its single caller until a second
  caller appears anywhere in the project, at which point it is
  promoted into MATH-SUPPORT/ or STATISTICS-SUPPORT/.
* TESTS/ and VALIDATION/ established as separate concerns: TESTS/
  will hold data-driven COBOL test runners, one per source file
  rather than one per function; VALIDATION/ will hold independently
  sourced expected values, never derived from this project's own
  reasoning, so that every function is checked against evidence
  external to itself.
* DOCS/ holds architecture-decision records, design philosophy, and
  a call-graph diagram that will be generated directly from each
  file's own REPOSITORY paragraph rather than drawn and maintained
  by hand.
* MAINFRAME/ is an explicit, honestly empty placeholder for the
  JCL, DB2, and CICS artifacts this project will gain as mainframe
  proficiency develops; it is not populated with speculative content.
* TOOLS/ holds this project's own automation: a dependency-ordered
  local compile check and a call-graph generator, both driven by the
  same REPOSITORY-paragraph parsing the compiler itself already
  enforces.

Conventions established in this commit:
* PROJECT-CONVENTIONS.md states, and binds, this project's core
  design constraint: every COBOL and FORTRAN file in SRC/ must
  remain conformant with a modern IBM z/OS compiler, not only with
  GnuCOBOL, the compiler used for local development and continuous
  integration.
* Every function's future formula and test fixture will carry a
  pinpoint citation, author, title, publisher, city, year, and page,
  to an independent, named source, never to this project's own
  derivation.

Tooling:
* .github/workflows/build.yml compiles the project on a clean,
  disposable GitHub-hosted runner on every push, so the build badge
  in README.md reflects a reproducible, independently verifiable
  result rather than a manual claim.

Status: scaffold only. See README.md for the full roadmap and the
current dependency ordering of planned work.
