# COBOL-financial-functions

![build status](https://github.com/Ignatz-CastroR/COBOL-financial-functions/actions/workflows/build.yml/badge.svg)
![license](https://img.shields.io/badge/license-MIT-blue.svg)

A library of advanced financial, actuarial, and statistical functions
written in mainframe-conformant COBOL, built as a real, tested,
professionally organized codebase rather than a demonstration script.

## Purpose

This project exists to demonstrate advanced, production-grade COBOL
skill in the specific domains where COBOL remains in active industry
demand: banking, insurance, and government finance. Every function here
is a pure computation: numbers in, a number out, no hidden state, so
that the library can be trusted, tested, and reused the way a real
enterprise function library would be.

## Design philosophy

Two decisions shape everything in this repository:

* **Functions, not systems.** This is a library, not an application. It
  does not keep ledgers, does not manage state, and deliberately does
  not attempt full accounting, that is a different category of software
  and a different, future project [see Roadmap below].
* **Fixed-point decimal arithmetic throughout.** Every monetary
  calculation here uses COBOL's native fixed-point and packed-decimal
  arithmetic. This is not a stylistic choice: floating-point rounding
  error is precisely the failure mode that fixed-point decimal
  arithmetic exists to eliminate, and it is why COBOL remains the
  compiler of choice for financial computation in the industries this
  project targets.

## Mainframe conformance

Every COBOL and FORTRAN file in `SRC/` is written to remain conformant
with a modern IBM z/OS compiler, not only with GnuCOBOL, the compiler
used for local development and continuous integration. See
`PROJECT-CONVENTIONS.md` for the specific rules this implies, and
`MAINFRAME/README.md` for the planned JCL, DB2, and CICS deployment
artifacts that will eventually accompany this codebase on an actual
mainframe.

## Project structure

```
COBOL-financial-functions/
    SRC/
        TIME-VALUE-MONEY/              Present value, future value,
                                        annuities, perpetuities, NPV, IRR
        AMORTIZATION/                  Loan amortization schedules
        DEPRECIATION/                  Straight-line, declining-balance,
                                        sum-of-years-digits
        BONDS-FIXED-INCOME/            Bond pricing, yield, duration,
                                        convexity
        CURRENCY-ROUNDING/             Fixed-point rounding and
                                        currency-conversion rules
        STATISTICS-SUPPORT/            Private statistical primitives
        STATISTICS-RISK/               Variance, correlation, VaR-related
                                        risk functions
        ACTUARIAL-LIFE-CONTINGENCIES/  Survival probabilities, life
                                        annuities, insurance present
                                        values, reserves
        MATH-SUPPORT/                  Shared mathematical primitives
                                        with fan-in greater than one
        FORTRAN-MODULES/               Bounded, clearly justified
                                        heavy-computation routines
    COPYBOOKS/      Shared data structures used across modules
    TESTS/          Data-driven test runners, one per source file
    VALIDATION/     Independent oracle data [Lua reference
                     implementation, solved-problem fixtures]
    DOCS/           Architecture decisions, design philosophy, and
                     generated call-graph diagrams
    TOOLS/          Local compile-check and call-graph generation
                     scripts
    MAINFRAME/      Placeholder for future JCL, DB2, and CICS artifacts
```

Each `SRC/` subfolder has its own `README.md` documenting exactly what
it implements, the conventions it assumes, and the pinpoint citation for
every function's formula and test fixtures. Follow the links above, or
browse directly.

## Dependency discipline

Functions are organized by fan-in, not only by domain. A function called
from a single place lives privately alongside its one caller. The moment
a second caller appears anywhere in the project, that function is
promoted to `MATH-SUPPORT/` or `STATISTICS-SUPPORT/`. The full call
graph is generated directly from each file's own `REPOSITORY` paragraph,
never drawn by hand, and lives in `DOCS/DIAGRAMS/`, regenerated by
`TOOLS/generate_callgraph.py` on every change.

## Testing

Every function is tested against an independently sourced expected
value, never against the author's own derivation. Test cases are stored
as data, not as bespoke COBOL programs per function; one COBOL test
runner per source file reads its fixture data and asserts every function
that file declares. See `TESTS/README.md` for the full discipline, and
`VALIDATION/README.md` for how the Lua reference implementation and the
solved-problem sefers listed below serve as independent oracles.

## Building locally

```
python3 TOOLS/compile_check.py
```

This compiles every file under `SRC/` with GnuCOBOL, in dependency
order, and reports the first failure with full compiler output rather
than a wall of downstream errors. See `TOOLS/README.md` for details and
for `generate_callgraph.py`.

## Continuous integration

Every push is compiled and tested automatically on a clean GitHub-hosted
runner; the badge at the top of this file reflects the result of the
most recent run, not a manual claim. See the Actions tab for the full,
independently reproducible log of any given build.

## Roadmap

Listed in build order; nothing below is started before the item above it
has a tagged, documented v1:

1. This repository, a finished, versioned v1 of the deterministic
   financial, actuarial, and statistical function library.
2. Independent `MATH-SUPPORT` and `STATISTICS-SUPPORT` repositories,
   extracted with full commit history once proven inside this project.
3. A stochastic-calculus pricing tier [option pricing, interest-rate
   term-structure models] extending this project's `BONDS-FIXED-INCOME`
   and adding a new module.
4. A US-focused COBOL accounting system, consuming this project's
   `DEPRECIATION`, `CURRENCY-ROUNDING`, and `TIME-VALUE-MONEY` functions
   as a dependency.
5. A graphical, GnuCOBOL-native scientific calculator, as a separate
   skills showcase.
